## Claim helper interface and tested boundaries

`claim(marker_pr_number, host_nonce, api=denied)` derives all authority from actual GitHub snapshots and returns a one-time fresh-winner Ticket only after separate draft repair PR persistence and final source/marker/head/receipt revalidation. An active/orphaned first attempt blocks the second. `finish(ticket, outcome, task_stopped=True, api=denied)` is called by the native coordinator AFTER stopping work, not by still-running repair/review/test code; it records failure/rejection and closes without merge. Both methods retain any ambiguous state, no automatic retries/resumes/ref resets/deletes. Public receipt nonce is correlation, not a credential/private thread ID. Current connected GitHub app profile ID276981287 matches public repository ownerSykezzz ID276981287 (read-only verification); no authentication store inspected.

API callback uses fixed repositorySykezzz/gamgui (except GET/user for existing connected identity) and bounded REST-shaped GitHub snapshots. Contents responses supply decoded bounded content_json; normalized connector responses must not omit mandatory head/base/provenance/draft/state/commit data. The callback must implement atomic create-only POST/git/refs; never map an upsert/update-ref tool to claim creation. Source itself has no HTTP/subprocess/token/service implementation and denies absent callback. The normal native task uses existing authorized GitHub operations for metadata coordination; all actual repository build/test/repair work stays inside the verified sandbox. No new infrastructure is provisioned by importing this helper.

Before independent review/full exactSHA CI, remove the initial .github/repair-attempts receipt with a normal descendant commit, never force/reset the branch. `candidate_paths()` rejects receipt/request/workflow/security/unrelated paths in the final base-to-candidate diff and allows only the established narrow GAM bump/build/test files. Original receipt remains readable by immutable commitSHA in PR history for attempt accounting. Ticket never authorizes merge. Existing exactSHA independent review/fullCI/required human reviews/protections remain separate mandatory publisher gates.
